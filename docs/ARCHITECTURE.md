# Architecture & Data Contracts

Slime Monsters from Outer Space is a browser JRPG built on **Phaser 4.2.1** (npm) with **Vite 8**.
Everything a build agent needs to know about module layout, data formats, and conventions lives here.
`docs/DESIGN.md` says *what* the game is; this file says *how it is wired*.

## 1. Stack and hard rules

| Thing | Decision |
|---|---|
| Engine | Phaser 4.2.1, imported as `import Phaser from 'phaser'`. API reference: `docs/PHASER_API_DIGEST.md` (signatures) and `node_modules/phaser/types/phaser.d.ts` (full JSDoc). Topic guides: `node_modules/phaser/skills/*/SKILL.md`. **Phaser 4, not 3**: no `preFX/postFX/setPipeline`; filters are `obj.enableFilters(); obj.filters.internal.addX()`; tint-fill is `setTint(c).setTintMode(Phaser.TintModes.FILL)`; `roundPixels` must be set explicitly; `RenderTexture.draw()` needs `.render()`; `Math.TAU` is 2π. |
| Build | `npm run dev` (Vite), `npm run build` → `dist/` (`base: './'` so GitHub Pages works). |
| Resolution | **256×224** internal (SNES), `pixelArt: true`, `roundPixels: true`, integer-scaled to the window (see `src/config.js`). Never place anything at fractional pixels. |
| Tiles | 16×16. Overworld character sprites 16×24 (origin 0.5,1 at the feet). Enemy battle sprites 32×32 / 48×48 / 64×64. Portraits 32×32. |
| Art | 100% generated by `python3 tools/gen_assets.py` from ASCII pixel maps in `tools/sprites/` and `tools/tiles/`. Output PNGs in `assets/generated/` **are committed** so the game runs without Python. `assets/generated/manifest.json` describes every sheet. No third-party art. |
| Audio | 100% synthesized at runtime via WebAudio (`src/audio/`). No audio files. |
| Font | Press Start 2P (`assets/fonts/`, OFL) at 8px via Phaser `Text` with `fontFamily: '"Press Start 2P"'`. Load the font (FontFace API) before the Title scene renders text. |
| Language | Plain ES modules, JSDoc types, no TypeScript, no bundler plugins. 2-space indent, semicolons, single quotes. |
| Persistence | `localStorage` only (key `smfos.save.<slot>`). |
| Tests | Node + Playwright (global install) in `tests/`. `npm test` runs everything. Zero console errors is a hard requirement. |

## 3. Art pipeline

### 3.1 Sprite sheet text format (`tools/sprites/<name>.txt`)

```
# comment lines start with #
name: lucky
frame: 16x24
palette:
  . = transparent
  p = #ff5fd2     # pink slime
  P = #ff9ae6     # pink highlight
  g = #39ff8a     # green glow
  k = #141018     # outline
anim: walk_down  frames: 0 1 0 2  fps: 8
anim: walk_up    frames: 3 4 3 5  fps: 8
anim: walk_left  frames: 6 7 6 8  fps: 8
anim: walk_right frames: 6 7 6 8  fps: 8  flipX: true
anim: idle_down  frames: 0        fps: 1

frame 0: down stand
................
......kkkk......
.....kppppk.....
(… exactly 24 rows of exactly 16 chars …)

frame 1: down step a
…
```

Rules: every frame is exactly `frame` wide × high; chars not in the palette are an error; frames are
laid out left-to-right in one row in the PNG (`assets/generated/<name>.png`); the manifest records
`{ "type": "spritesheet", "frameWidth", "frameHeight", "frames", "anims": [{key, frames, fps, repeat, flipX}] }`.
Animation keys in Phaser are `<name>_<anim>` (e.g. `lucky_walk_down`). `flipX` animations are
registered as the same frames and the entity flips the sprite. Palette swaps: a sheet can declare
`variant: ryan_slimed  from: ryan  swap: s=#8bff9a,…` to produce a recolored copy.

Character sheets needed by the engine (minimum): `walk_down/up/left` (3 frames each), `idle_*`.
Optional: `emote`, `hurt`, `melt`. Battle sheets (`<name>_battle.txt`, 32×32): `idle` (2 fr),
`attack` (3 fr), `hurt` (1 fr), `ko` (1 fr), `riff` (2 fr).

### 3.2 Tileset text format (`tools/tiles/<tileset>.txt`)

```
name: minneapolis
tile: 16x16
palette: (same syntax)
tile snow:            # name used by maps
solid: false
(16 rows × 16 chars)

tile brick_wall:
solid: true
…
```

Output: `assets/generated/tiles_<tileset>.png` (tiles packed 16 per row) and a manifest entry
`{ "type": "tileset", "tileWidth", "tileHeight", "tiles": { "snow": { "index": 0, "solid": false }, … } }`.
Tile index 0 is always the first declared tile; maps use `-1` / blank for empty.

### 3.3 UI sheet

`tools/ui/ui.txt` declares named regions (frame corners/edges, cursor hand, meter segments, icons)
in one PNG; manifest `{ "type": "atlas", "frames": { "win_tl": {x,y,w,h}, … } }`.

## 4. Map format (`src/data/maps/<mapId>.json`)

Maps are authored as ASCII rows with a legend, so humans and agents can draw them.

```jsonc
{
  "id": "alley",
  "name": "Alley behind Palmer's",
  "tileset": "minneapolis",          // manifest tileset name
  "music": "snow",                    // song id, or null
  "ambient": "wind",                  // optional looping SFX id
  "battleBackground": "street",       // default battle backdrop for on-map encounters
  "legend": { "#": "brick_wall", ".": "snow", "=": "sidewalk", "D": "dumpster", "W": "window_lit" },
  "layers": {
    "ground": [ "################", "#..............#", … ],   // required; ' ' = empty
    "deco":   [ "                ", "   D   D        ", … ],   // optional; same size; drawn above ground
    "over":   [ … ]                                             // optional; drawn ABOVE sprites (awnings, tree tops)
  },
  "spawn": { "x": 3, "y": 10, "facing": "right" },             // default when entering without a target
  "entities": [
    { "id": "phoenix", "type": "npc", "sprite": "phoenix", "x": 12, "y": 8, "facing": "left",
      "behavior": "idle", "script": "alley_phoenix", "condition": "!flags.metPhoenix" },
    { "id": "sign", "type": "object", "sprite": "sign_palmers", "x": 6, "y": 2, "script": "alley_sign", "solid": true },
    { "id": "to_street", "type": "exit", "x": 0, "y": 9, "w": 1, "h": 2,
      "to": { "map": "street_west_bank", "x": 29, "y": 9, "facing": "left" } },
    { "id": "crash_trigger", "type": "trigger", "x": 10, "y": 8, "w": 3, "h": 3, "script": "ep0_crash", "once": true },
    { "id": "cop_a", "type": "enemy", "sprite": "cop", "x": 20, "y": 5, "encounter": "street_cop_duo",
      "behavior": "chase", "condition": "!flags.cleared_cop_a", "setOnWin": "flags.cleared_cop_a" },
    { "id": "bajonka", "type": "save", "sprite": "bajonka", "x": 2, "y": 2, "condition": "flags.hasBajonka" }
  ]
}
```

Rules:
- Collision = tile `solid` flags from the tileset, OR'd across `ground` and `deco`, plus `solid` entities.
- All coordinates are tile coordinates. Entities stand on a tile; sprites are drawn with the feet at the tile's bottom.
- `condition` is evaluated when the map loads (and re-evaluated after every script ends); false ⇒ entity not present.
- `behavior`: `idle` | `wander` (random steps within `radius`, default 2) | `patrol` (`path`: string of `UDLR`) | `chase` (enemy walks toward the player when within `sight` tiles, default 5; touching starts the encounter) | `static`.
- `exit` entities teleport on overlap with a fade. `trigger` entities run `script` on overlap (`once` sets `flags.trig_<mapId>_<id>` automatically).
- `type: "save"` entities are Bajonka save points: interacting opens the save prompt (and plays the sneeze).
- Maps may list `"encounters": { "rate": 0, "pool": [] }` for FF-style random battles, but Chapter 1 uses on-map enemies only (`rate: 0`).

The `MapLoader` resolves legend names to tile indices through the manifest and builds the tilemap with
`this.make.tilemap({ tileWidth: 16, tileHeight: 16, width, height })` + `createBlankLayer` + `putTilesAt`.
Depths: ground 0, deco 1, entities `y` (pixel y of the feet, for y-sorting), over 100. UIScene is a separate scene above.

## 5. Event scripts (`src/data/scripts/<scriptId>.json`)

A script is a JSON array of commands run sequentially by `EventRunner` (async; one command at a time;
player input is locked while a script runs unless the command says otherwise). Several scripts can live in
one file: `{ "alley_phoenix": [ … ], "alley_sign": [ … ] }`. Script ids are globally unique.

### 5.1 Commands

| Command | Meaning |
|---|---|
| `{"say": "text", "who": "phoenix", "portrait": "phoenix_tired"}` | Dialogue box. `who` = character id (name tag + default portrait) or `"narrator"` (caption-style box, no tag) or `"ryan_caption"` (Ryan's rigid square internal caption). `portrait` optional override. Text markup: `\n` newline, `{pause:300}`, `{speed:fast|slow|instant}`, `{color:pink}` … `{/color}`, `{shake}` … `{/shake}`. Box auto-paginates on overflow. |
| `{"choice": [{"text": "Yes", "then": [ … ]}, {"text": "No", "then": [ … ]}]}` | Choice menu under the dialogue box. |
| `{"if": "<condition>", "then": [ … ], "else": [ … ]}` | Branch (section 5.3). |
| `{"set": {"flags.metPhoenix": true, "vars.coffeeCount": 2}}` | Assign into GameState. Dotted paths. |
| `{"inc": {"vars.coffeeCount": 1}}` | Increment. |
| `{"give": {"item": "pizza_slice", "qty": 1}}` / `{"give": {"money": 4}}` / `{"take": …}` | Inventory & money. |
| `{"party": {"add": "phoenix"}}` / `{"party": {"remove": "brian"}}` / `{"party": {"heal": true}}` | Party roster. |
| `{"move": {"who": "phoenix", "path": "LLUU", "wait": true, "speed": "walk|run"}}` | Walk an entity (`"player"` allowed). `path` chars `U D L R` and `.` (pause one step). |
| `{"face": {"who": "lucky", "dir": "up"}}` / `{"face": {"who":"ryan","toward":"player"}}` | Facing. |
| `{"teleport": {"map": "apartment", "x": 5, "y": 6, "facing": "down"}}` | Change map with fade. |
| `{"spawn": {"id": "ryan", "sprite": "ryan", "x": 1, "y": 5, "facing": "right"}}` / `{"despawn": "ryan"}` | Temporary entities for cutscenes. |
| `{"sprite": {"who": "ryan", "sheet": "ryan_eternity"}}` / `{"anim": {"who": "ryan", "key": "ryan_drum", "wait": false}}` | Swap sheet / play animation. |
| `{"emote": {"who": "lucky", "type": "!"}}` | Emote bubble: `! ? … ♪ ♥ zzz`. |
| `{"camera": {"shake": 400, "intensity": 0.01}}` / `{"camera": {"flash": 200, "color": "#ffffff"}}` / `{"camera": {"fade": "out", "ms": 400}}` / `{"camera": {"pan": {"x":..,"y":..,"ms":..}}}` / `{"camera": {"follow": "player"}}` | Camera effects. |
| `{"wait": 500}` | Milliseconds. |
| `{"caption": "ONE MONTH LATER", "ms": 1800}` | Title card over black. |
| `{"music": "rehearsal"}` / `{"music": null}` / `{"sfx": "squelch"}` | Audio. |
| `{"battle": "encounterId", "onWin": [ … ], "onLose": "gameover" | [ … ]}` | Run a battle; continue after. |
| `{"scene": "freefall", "data": {}}` | Run a special scene; resume after it calls back. |
| `{"save": true}` | Open the save prompt (Bajonka). |
| `{"shop": "pawnshop"}` | Open a shop (`src/data/shops.json`). |
| `{"run": "otherScriptId"}` | Call another script (returns when done). |
| `{"label": "x"}` / `{"goto": "x"}` | Local jumps within the same script. |
| `{"end": true}` | Stop the script early. |
| `{"setEntity": {"id": "cop_a", "behavior": "idle"}}` | Tweak a live entity. |
| `{"gameover": "text"}` | Straight to Game Over. |

### 5.2 Script hooks

- Map entities: `script` (interact / overlap), `onDefeat` for enemies.
- Maps: `"onEnter": "scriptId"` runs after load; `"onFirstEnter"` once.
- Encounters: `"script"` → key in `BattleScripts.js` (code, not JSON, because mid-battle logic needs model access).
- Characters: `"onJoin"` script.

### 5.3 Conditions

Tiny safe evaluator (no `eval`): identifiers resolve against `GameState` (`flags.x`, `vars.x`, `money`,
`party.has('ryan')`, `party.size`, `inventory.has('item')`, `inventory.count('item')`, `level('lucky')`),
operators `! && || == != < <= > >= + -`, parentheses, numbers, single-quoted strings.

## 6. Game state & save format

```jsonc
{
  "version": 1,
  "chapter": 1,
  "map": "apartment", "x": 5, "y": 6, "facing": "down",
  "flags": { "metPhoenix": true },
  "vars": { "coffeeCount": 2 },
  "money": 4,
  "party": [ { "id": "lucky", "level": 3, "xp": 120, "hp": 54, "amp": 12, "equip": { "instrument": "beatup_guitar", "accessory": null }, "status": [] } ],
  "roster": ["lucky", "phoenix", "ryan"],      // everyone who has ever joined (for menus/story)
  "inventory": [ { "id": "pizza_slice", "qty": 2 } ],
  "meter": 0,                                  // shared party meter carried between battles? (design decides; default resets)
  "playtimeMs": 123456,
  "savedAt": "2026-10-08T00:00:00Z"
}
```
`GameState` is a plain object + helper methods; scenes never mutate it except through `GameState` / `Party` / `Inventory` APIs. `localStorage` keys: `smfos.save.1..3`, `smfos.settings`.

## 7. Audio contracts

```js
// src/audio/songs/rehearsal.js
export default {
  id: 'rehearsal', bpm: 196, beatsPerBar: 4, stepsPerBeat: 4,        // 16th-note grid; timeSig via beatsPerBar (7 for 7/8 feel w/ stepsPerBeat 2)
  loop: true,
  channels: {
    pulse1: { wave: 'pulse', duty: 0.5, volume: 0.5, patterns: { A: 'C4 . . C4 D#4 . G4 . …' } },
    pulse2: { wave: 'pulse', duty: 0.25, volume: 0.35, patterns: { … } },
    tri:    { wave: 'triangle', volume: 0.6, patterns: { … } },
    noise:  { wave: 'noise', volume: 0.3, patterns: { A: 'k . h . s . h . …' } }   // k kick, s snare, h hat, o open hat
  },
  order: [ { pulse1: 'A', pulse2: 'A', tri: 'A', noise: 'A' }, … ]   // one entry per bar
};
```
Note tokens: `C4`..`B8`, `.` rest, `=` hold previous, `C4~` slide into, `C4!` accent (louder). The sequencer
schedules 100 ms ahead on a 25 ms timer, using `audioCtx.currentTime`. Music API: `audio.playMusic(id, {fade})`,
`audio.stopMusic({fade})`, `audio.sfx(name)`, `audio.setVolume(music, sfx)`. The engine takes the AudioContext
from Phaser (`scene.sound.context`) and connects to `scene.sound.destination` so Phaser's unlock-on-first-input and
mute apply. If Phaser falls back to no-audio, create our own context and resume it on first keydown.

SFX are code recipes (`sfx.js`): `cursor, confirm, cancel, text_blip, hit, crit, miss, squelch, slime_pop, kraaang,
level_up, item, door, sneeze, feedback, drum_hit, cymbal, ko, flee, save`.

## 8. Battle model contract

`BattleModel` is pure JS: `new BattleModel({ party, enemies, rules, rng })`, `model.getTurnOrder()`, `model.act(actorId, action)`,
`model.enemyDecide(enemyId)`, `model.events` (an array of presentation events emitted per action:
`{ type: 'damage', target, amount, crit }`, `{ type: 'text', text }`, `{ type: 'anim', who, key }`, `{ type: 'meter', value }`,
`{ type: 'transform', who, sheet }`, `{ type: 'status', target, status, on }`, `{ type: 'ko', who }`, `{ type: 'win' }`, `{ type: 'lose' }`, `{ type: 'flee' }`).
`BattleScene` drains events and animates them one by one. Scripted battles register hooks:
`{ onStart(model), onTurnStart(model, turn), onHpBelow(model, who, pct), onRound(model, n), onDefeat(model, who) }` returning
events to inject (e.g. Ryan's transformation). Formulas live in `formulas.js` and are the numbers in `docs/DESIGN.md`.
`tests/battle.test.mjs` must cover: damage formula, turn order ties, meter fill, KO handling, win/lose, each scripted battle's hooks.

## 9. Debug API (required; tests depend on it)

Installed by `src/engine/Debug.js` on `window.__slime`:

```js
window.__slime = {
  ready,                        // Promise resolved when TitleScene is up
  game, state: GameState,
  scene: () => activeSceneKey,  // 'Title' | 'Explore' | 'Battle' | 'Menu' | 'Freefall' | 'GameOver'
  newGame(), load(slot), save(slot),
  warp(mapId, x, y),            // from anywhere in Explore
  setFlag(path, value), give(itemId, qty), setMoney(n), addParty(id), removeParty(id),
  startBattle(encounterId),     // resolves with 'win' | 'lose' | 'flee'
  runScript(scriptId),          // resolves when done
  press(action),                // 'up','down','left','right','confirm','cancel','menu','run' — simulated key tap
  hold(action, ms),
  textInstant(bool),            // typewriter off
  autoAdvance(bool),            // dialogue advances itself; choices pick the first option unless chooseIndex is set
  chooseIndex: 0,
  waitFor(predicate, timeoutMs),
  snapshot(),                   // { map, x, y, flags, party, inventory, money }
  lastErrors: []                // console errors captured
};
```
URL params: `?debug=1` (overlay with map/x/y/fps), `?fast=1` (instant text, 4× transitions), `?mute=1`, `?slot=N`.

## 10. Scene flow

```
Boot → Title ⇄ (New/Continue) → Explore ──(exit)──► Explore (same scene, swaps map)
                                   │ interact/overlap → EventRunner (locks input, drives UIScene)
                                   │ enemy touch / {"battle"} → Battle (Explore sleeps; UIScene stays for text)
                                   │ {"scene":"freefall"} → Freefall → back
                                   │ menu key → MenuScene (overlay; Explore paused)
Battle ──win──► Explore (resume, rewards shown) ──lose──► GameOver → Title
```
`UIScene` is launched once after Boot and never stopped; it exposes `ui.say()`, `ui.choice()`, `ui.caption()`,
`ui.fade()` returning Promises. Explore and Battle are the only scenes that read gameplay input; `Input.js`
exposes `justPressed(action)`, `isDown(action)`, plus a `scene.input.keyboard` fallback for menus.

## 11. Conventions that keep this SNES

- Only integer positions and scales. Camera `roundPixels = true`. Fonts at 8 px exactly; line height 10 or 12.
- Palette discipline: each sheet ≤ 16 colors; outlines `#141018`; Lucky's slime hue is driven by mood via palette variants (`lucky`, `lucky_rage`, `lucky_deflated`), not runtime tinting.
- Transitions: fade (black), flash (white), shake; battle entry = "static burst" (horizontal slices sliding) built from a RenderTexture snapshot; optional pixelate filter when WebGL.
- Text speed default 1 char / 30 ms, `confirm` to skip to end of page, then to advance; `cancel` does nothing in dialogue.
- Nothing blocks on `setTimeout`; use `scene.time` and tweens so `?fast=1` can scale time.
